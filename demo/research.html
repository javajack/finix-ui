Selection philosophy
Finix UI is a plain HTML/CSS/JS distillation — not a copy — of the best free UX patterns in the shadcn ecosystem. Visual fidelity comes from porting the shared OKLCH token system verbatim; behavior is rebuilt on modern platform primitives (<dialog>, Popover API, <details name>) instead of React/Radix. All sources are MIT or Apache-2.0 licensed.
Surface hierarchy
Depth is encoded by lightness — every layer has a named token. Wells sit below surfaces; overlays float above them.
--background · canvas (dot-grid ground)
--card · surface (cards, tables, panels)
--well · inset (toolbars, column wells, code, headers)
--popover · overlay (menus, dialogs — lighter than cards in dark)

Plus --hover for every pointer-over fill and --border-soft for internal dividers — structural container borders always use --border.

Why the aesthetic survives the port

The entire shadcn ecosystem is visually consistent because every library consumes the same CSS-variable token contract (--background, --primary, --radius, --chart-1…5, …). That token layer is already plain CSS — Finix ports it verbatim, in OKLCH, so every component here is pixel-faithful to the originals.

Interactions are rebuilt on 2026-baseline platform features: <dialog> gives focus-trapping for free, the Popover API gives top-layer menus, <details name> gives exclusive accordions, and @starting-style transitions reproduce the Radix entry/exit animations.

For AI agents

Finix UI is designed for machine consumption: semantic class names (fx-btn fx-btn--outline) instead of utility soup, data-attribute behaviors (data-fx-open, popovertarget), and a machine-readable registry:

finix-ui/manifest.json · finix-ui/llms.txt

Every component maps to: markup snippet → CSS classes → optional JS hook. No build step, works in any server-rendered stack.
